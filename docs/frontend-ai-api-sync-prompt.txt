You are integrating against the Laravel backend API. Use this as the canonical API contract for /api/v1.
Base URL examples: http://aai-api.test/api , https://api.aai.md/api , https://aai-api.bridgebyte.md/api

Global rules:
1) Authentication: Protected endpoints require `Authorization: Bearer <token>` (Sanctum). Endpoints under middleware `verified` additionally require verified email; otherwise forbidden.
2) Request key format: backend accepts camelCase in API payload/query and normalizes to snake_case internally via BaseFormRequest. Keep sending camelCase from frontend.
3) Pagination: paginated list endpoints return Laravel paginator shape with `data` plus `links` and `meta`.
4) Validation errors: 422 JSON shape `{ message: string, errors: { ...fieldErrors } }`.
5) Unauthorized vs Forbidden: 401 when token missing/invalid; 403 when authenticated but not allowed by Gate/Policy/verified middleware.
6) Not found: 404 for missing models and for visibility-protected records (e.g., unpublished post/event/file for public caller).
7) Server errors: mutating endpoints are wrapped in DB transactions and may return 500 with user-friendly `message` when an unexpected exception occurs (unless debug mode rethrows).
8) Known backend inconsistency: route `GET /api/v1/users/invitation/{user}` is registered, but `UserController@showInvitation` method is not present in current code; treat this endpoint as unstable until backend fixes it.

Frontend implementation guidance:
1) Build a centralized API client that always captures `{status, message, errors}` and maps 401/403/422 consistently in UI.
2) For endpoints with limited/full variants, design type unions (e.g., `LimitedPost | Post`) and feature-flag UI by field existence (e.g., `can`).
3) For file download/thumbnail, expect binary responses (`application/octet-stream`) and handle 404 as either missing file or not authorized to view it.
4) For id-or-slug show endpoints (`posts`, `events`, `files`), pass either numeric ID or slug as path param in the same route.
5) Respect numeric-only constraints for secured mutating routes where applicable (`{user}`, `{post}`, `{event}`, `{file}`, `{file_folder}`).
6) Treat `GET /api/v1/users/invitation/{user}` as non-production-ready until backend method is implemented.
